# 使用场景

> 从 [`idea.md`](idea.md) 的场景说明展开，用于校验需求与验收标准。
> 每个场景都标注「触发 → 动作 → 结果 → 不打断什么」。

---

## 场景 A：对话中触发新灵感，稍后处理（核心场景）

1. 用户在跟 AI 讨论「某技术方案」时，看到 AI 回复里出现一个陌生概念「Retrieval-Augmented Generation」。
2. 用户**不想此刻深究**，只想先把它记下来。
3. 用户用鼠标**选中**这个词，聊天页面选区旁浮出一个「随手抽屉」小按钮。
4. 点一下 → 该词**存入抽屉**，按钮消失，对话继续，无任何弹窗打断。
5. 用户继续专注当前对话；之后空闲时打开抽屉，对这条内容做追问 / 搜索。

> 校验点：收藏动作 ≤ 1 次点击 + 1 次选区；不离开对话、不弹大窗。

## 场景 B：不理解但需要搜索，不想开新页（核心场景）

1. 对话中遇到一个看不懂的报错信息片段。
2. 用户选中该片段，收藏进抽屉。
3. 稍后，用户在**同一个页面**打开「临时追问」小窗，选这条报错片段。
4. 选择「**不加入上下文**」（只想独立搞清楚这个报错），发起追问。
5. 答案在浮窗内就地返回，无需新开页面搜索。

> 校验点：追问在当前页面浮窗内完成；「不加入上下文」时答案不依赖当前对话。

## 场景 C：多条目合并追问（多选）

1. 用户在一段长对话里陆续收藏了 3 个相关的关键词（如：`A`、`B`、`C`）。
2. 空闲时打开抽屉，**多选** A、B、C 三条。
3. 在浮窗里输入一个问题（如「这三者之间是什么关系？」），选择「加入上下文」。
4. 系统把 A+B+C+当前对话上下文一起作为追问背景，答案在浮窗返回。

> 校验点：支持抽屉多选；支持追加自定义问题文本；「加入上下文」生效。

## 场景 D：直接用当前选区追问（不经抽屉）

1. 用户选中对话里一段文字，浮出「随手抽屉」按钮。
2. 除「收藏」外，还有一个「追问」入口。
3. 点「追问」→ 直接带这段选区打开临时追问小窗（可再选是否加上下文）。
4. 得到答案后，可选择是否顺便把这段也收藏进抽屉。

> 校验点：选区既是「存」的入口，也是「问」的入口。

---

## 场景边界（非目标，先不做）

- 抽屉**自动**整理 / 自动打标签 / 自动分类（二期可选）。
- 追问**带完整工具 / 子代理**的深度 agent turn（二期）。
- 多会话之间的抽屉共享 / 全局搜索（二期，需确认数据模型）。
