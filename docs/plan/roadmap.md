## M1 — MVP（核心闭环）
**目标**：跑通「选中 → 存 → 追问 → 回答案」最小闭环。

- [x] FR-1 选区收藏（Notion 式选区菜单 + 持久化，2026-08-20；浏览器目检待办）
- [x] FR-2 抽屉标签墙 / 单选多选 / 删除（2026-08-20）
- [ ] FR-3 追问（选 1 条或多条 + 自定义问题 + 一次性 `llm.stream` 答案；当前追问选中已通，自定义问题合并待接）
- [x] 「是否加入上下文」开关：加入 = 宿主读当前活动会话最近消息并截断；不加入 = 独立问答；两模式均不写主对话
- [x] `ask` 接入 `ctx.llm.stream`，一次性汇总文本答案
- [x] `ask` 模型路由解析：优先当前会话 `request/header`，否则使用默认模型
- [x] FR-4.2 常驻入口 + FR-4.3 收藏轻反馈（不打断）（2026-08-20）

**交付物**：满足 [`requirements.md`](../requirements/requirements.md) 的 MVP 验收 AC-1~AC-5。
**验收**：场景 A、B、C、D 基本可走通；不写进主对话（不加上下文时）。

**目标**：进阶能力，按需排期。

- [ ] 追问升级为完整 agent turn（带工具 / 子代理）
- [ ] 抽屉全局搜索 / 多会话共享
- [ ] 快捷键触发收藏 / 追问
- [ ] 设置页（默认开关、命名自定义）

## 范围纪律（防「无限做加法」）

- **M1 的唯一完成标准 = AC-1 ~ AC-5 通过 + 卸载无残留**；验收之外的需求一律不插队。
- 新想法先记进 [`backlog.md`](backlog.md) 对应里程碑或下方「非目标」清单，**不直接改 M0/M1 任务**；改需求 = 先改 AC / 契约，再动代码。
- 营销内容在开发期冻结：M0/M1 期间不再生成新营销物料，专注插件功能与体验。

### 非目标 / 明确推迟（Out of Scope）

| 项 | 状态 |
|---|---|
| 追问留档 / 追问历史 | 推迟 M3（MVP 对齐 `/btw`「看完即弃」，ADR-008） |
| 标签 / 去重 / 按会话归档 | 推迟 M2+（R5） |
| 流式返回 | 推迟 M2 |
| 完整 agent turn | 推迟 M3 |
| 快捷键 | 推迟 M3 |
| 云同步 / 跨设备 / 多用户 / 账号体系 | 不做（规划外） |
| 导出 / 导入、付费 | 不做（规划外） |
| E2E 自动化测试 | 后置（MVP 只做契约测试 + 注入自检） |
