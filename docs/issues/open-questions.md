# 当前需要处理的问题（Open Questions）

> 这些问题**阻塞设计 / 实现**，需要先拍板。每项给出候选与推荐。

---

## Q1：命名 —— ✅ 已定
- **决议**：插件名「**随手抽屉**」（英文 **Stash**），存储地叫「**抽屉**」，包名 `dsh-stash`。
- **原文**：原文写「灵感库，还没想好如何命名」——现已定名为「抽屉」。
- **备注**：浮窗显示文案可后续微调（如「临时追问 / 快问」），不影响结构。

## Q2：「加入上下文」的上下文来源（阻塞实现）
- **候选**（见 ADR-003）：
  - A. 宿主侧解析整段对话（`session`/`session-query`）—— 推荐，但 MVP 复杂一点。
  - B. 会话作用域隐形组件灌数据。
  - C. MVP 先只带「选中文本 + 手动追加」。
- **推荐**：**M1 先做 C**，**M2 上 A**。
- **需要你确认**：MVP 阶段是否接受「上下文 = 选中内容 + 手动追加」，暂不自动带整段对话？

## Q3：「临时追问」的深度（阻塞后端）
- **候选**：一次性无工具问答（MVP） vs 完整 agent turn（带工具/子代理）。
- **推荐**：MVP 用一次性问答，M3 升级完整 agent。
- **需要你确认**：追问是否需要调用工具 / 读文件 / 联网？还是纯文本问答即可？

## Q4：存储方案（阻塞 M0 编码）
- **候选**：`storage-domain`（schema 校验，推荐） vs `storage` JSON（更快）。
- **推荐**：`storage-domain`（持久可靠，官方范式）。
- **需要你确认**：抽屉数据是否需要跨设备 / 跨 profile 共享（若需要，可能影响存储选型）？

## Q5：抽屉作用域（影响数据模型）
- **候选**：全局（跨会话抽屉，ADR-006 已倾向） vs 按会话隔离。
- **推荐**：全局。
- **需要你确认**：你期望「同一个抽屉」在不同会话间共享，还是每个会话各自独立？

## Q6：追问结果是否流式（影响体验）
- **候选**：一次性返回（MVP） vs 流式打字机（M2）。
- **推荐**：MVP 一次性，M2 流式。

## Q7：入口方式（影响交互）
- **候选**：仅选区浮钮 / 仅浮窗常驻按钮 / 两者都要 / 加快捷键。
- **推荐**：选区浮钮（核心）+ 浮窗内按钮；快捷键 M3。
