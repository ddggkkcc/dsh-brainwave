# 风险与对策

> 每项给「风险 / 概率 / 影响 / 对策」。

---

## R1：对话 DOM 结构变化导致选区捕获失效
- **风险**：依赖对话内容容器判断选区，UI 改版后定位不稳。
- **概率**：中；**影响**：中（收藏/追问入口失效）。
- **对策**：用 `getSelection()` 纯文本 + 容器归属判断，不硬编码 class；选区浮钮作为**渐进增强**（即便定位不精确，浮窗内仍可手动输入追问兜底）。

## R2：`shell.overlay` root 作用域拿不到会话数据
- **风险**：「加入上下文」实现受阻。
- **概率**：确定（作用域已核实）。
- **对策**：走 ADR-003 宿主侧解析；MVP 先做 C 方案兜底。

## R3：LLM 直调的一次性问答与主对话模型/凭据不一致
- **风险**：追问用的 provider/model 需正确解析，否则报错或答非所问。
- **概率**：中；**影响**：中。
- **对策**：复用 `llm/stream` 事件捕获到的当前路由（super-injector daemon 示例做法），或读取当前会话模型配置。

## R4：热重载 / 卸载残留（DOM 监听、remote、存储句柄）
- **风险**：不挂 `ctx.effect` 会导致僵尸残留、重复注册。
- **概率**：中（不规范时）；**影响**：高。
- **对策**：铁律——所有资源注册挂 `ctx.effect`；选区监听、浮窗 DOM、remote 生命周期统一随 fiber 清理；每次改完跑 `dev_self_test`。

## R5：灵感库数据膨胀 / 无去重
- **风险**：重复收藏、条目过多。
- **概率**：中（长期）；**影响**：低~中。
- **对策**：M2 加去重提示 / 标签 / 归档；MVP 先接受。

## R6：上下文带入导致 token 超标
- **风险**：整段对话作为上下文可能过长。
- **概率**：中（M2 后）；**影响**：中。
- **对策**：宿主侧截断 / 摘要，或只带最近 N 轮；作为 M2 明确子任务。

## R7：远程调用权限 / 凭据
- **风险**：`ask` 触发 LLM 需要有效凭据与权限。
- **概率**：低（复用现有 llm 服务）；**影响**：高（若失效则追问不可用）。
- **对策**：复用宿主 `llm` 服务既有凭据链路；错误码 `llm-error` 友好回传。
